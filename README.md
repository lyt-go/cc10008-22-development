# 行为特征分析与事件溯源平台

面向用户行为打点采集、事件参数规范、会话重放、热力图分析、特征工程提取与行为标签体系管理的本地化数据分析应用平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 漏斗表单流失诊断（跨模块数据流）

漏斗诊断（`funnel`）与表单分析（`formfield`）共用 `frontend/src/data/diagnosis.ts` 这一条跨模块
数据流，把待处理漏斗的步骤读数与表单诊断的字段级放弃证据归因成新的「漏斗表单流失诊断数据报告」。
源数据在 `frontend/src/data/diagnosis-seed.ts`，生成结果独立持久化在
`behavior-event-trace-hub:diagnosis-v1`，不会覆盖模块自身的示例数据。

- **同一诊断版本**：`diagnosisVersion(漏斗, 表单)` 由两侧修订号拼成，表单侧提交的版本必须与漏斗侧一致，
  否则返回 `VERSION_MISMATCH` 拒绝凭据。
- **字段级流失原因**：报告带 `fieldCauses`（字段、原因、放弃量、证据完整度、归因角色）与保留的字段证据。
- **唯一归因**：每个步骤流失量只归入一个原因组，`attributionIndex` 与不变式校验保证不被拆分或重复计入。
- **两种仲裁口径**：`volume`（流失量优先，留高流失字段的优先原因报告）与 `evidence`
  （放弃证据完整度优先，留证据完整字段的原因组报告 + 次优字段清单）。两页可并排预览。
- **并发只留一份**：同版本并发生成返回 `CONCURRENT_SUBMISSION`；两个字段争抢同一首要流失原因时后到请求
  返回 `PRIMARY_CAUSE_CONFLICT`，并保留字段证据。所有拒绝都带 `token` 凭据。
- **清单取数**：表单分析清单的「流失绝对量」「流失占比」来自新生成的报告，同时保留报告编号与
  「漏斗表单流失诊断」来源；漏斗诊断页提供双端逐项比对（步骤分母 / 流失绝对量 / 流失占比 / 放弃字段 / 首要原因）。

核对口径：`FUNN-0002`（注册转化漏斗，四步分母 12000/9600/7800/5200，流失 2400/1800/2600/900）
与 `FORM-0002`（注册表单，`v2.3`）/ `FORM-0004`（注册表单短信渠道，`v2.1`）对应。
`FORM-0002` 在「验证码输入」步骤同时有「短信验证码」（1900 放弃、证据 0.66）与「图形验证码」
（520 放弃、证据 0.95）争抢首要原因：流失量优先留短信验证码，证据完整度优先留图形验证码 + 语音验证码
原因组，短信验证码进次优字段清单；两种口径流失总量均为 7700、流失占比 64.17%。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `behavior-event-trace-hub:entries` 这一项，或调用 `resetModule(模块)`。
